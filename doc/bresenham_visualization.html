Proč a jak to funguje


    
1. Problém

    
Úsečka je spojitá, ale rastr je mřížka celých pixelů. Musíme vybrat pixely, které leží „co nejblíž“ skutečné úsečce.
       Nejjednodušší řešení je to, co dělá LineRasterizerTrivial: spočítat k = dy/dx, q = y1 − k·x1
       a pro každé x nastavit y = round(k·x + q).

    
Funguje to, ale v každém kroku je potřeba násobení v plovoucí čárce a zaokrouhlení, navíc se může hromadit
       zaokrouhlovací chyba floatu. Bresenham (1962, plotter IBM) dává stejný výsledek pouze pomocí celočíselného sčítání a porovnání s nulou.


    
2. Klíčové pozorování (1. oktant: 0 ≤ dy ≤ dx)

    
Pokud je úsečka „spíš vodorovná“ (sklon 0 ≤ k ≤ 1), pak když se posuneme o jeden pixel v x, posune se skutečné y o k ≤ 1.
       Další pixel tedy může být jen jeden ze dvou kandidátů:

    
    
        
  • [x+1, y] – zůstat ve stejném řádku,
    • 
        
  • [x+1, y+1] – posunout se diagonálně.
    • 
    

    
Mezi nimi leží střed M = [x+1, y+½]. Stačí zjistit, jestli skutečná úsečka v tomto sloupci (bod T) prochází před, nebo za středem M.
       Tím se celé kreslení redukuje na otázku „ano/ne“ v každém kroku.


    
3. Odvození rozhodovací proměnné p

    
Úsečku zapíšeme implicitně – funkce F je nulová přesně na úsečce:

    
F(x, y) = dy·x − dx·y + c          (F = 0 na úsečce)

    
Dosadíme střed M. Když T leží v řádku yT, vyjde F(M) = dx·(yT − y − ½), takže:

    
F(M) < 0   ⇔   y_T < y + ½   ⇔   úsečka je blíž k [x+1, y]     → zůstat
F(M) ≥ 0   ⇔   y_T ≥ y + ½   ⇔   úsečka je blíž k [x+1, y+1]   → diagonálně

    
Kvůli zlomku ½ vynásobíme vše dvěma (znaménko se nezmění) a definujeme p = 2·F(M). Všechno je teď celočíselné.

    
Počáteční hodnota. Bod [x1, y1] leží na úsečce, tj. F(x1, y1) = 0. První střed je M = [x1+1, y1+½]:

    
p₀ = 2·F(x1+1, y1+½) = 2·(F(x1,y1) + dy − dx/2) = 2·dy − dx

    
Inkrementální aktualizace. Nemusíme F počítat znovu – stačí vědět, o kolik se změní, když se střed M posune:

    

        
rozhodnutíM se posune ozměna Fzměna p

        
zůstat (p < 0)[+1, 0]+dyd1 = 2·dy

        
diagonálně (p ≥ 0)[+1, +1]+dy − dxd2 = 2·(dy − dx)

    

    
Odtud přesně pseudokód z přednášky: d1 a d2 se spočítají jednou předem a ve smyčce se jen přičítají.


    
4. Intuice: p je „zvětšená chyba“

    
Hodnota e = p / (2·dx) je přímo vzdálenost (v pixelech) bodu T od středu M. Ve vizualizaci ji vidíš jako červenou/modrou čárku mezi M a T.

    
    
        
  • Krok o 1 v x → úsečka stoupne o k = dy/dx → e vzroste o k → p vzroste o 2·dx·k = 2·dy.
    • 
        
  • Když se posuneme i v y, referenční řádek se posune o celý pixel → e klesne o 1 → p klesne o 2·dx.
    • 
    

    
Proto je d2 = 2·dy − 2·dx. Násobení 2·dx je jen trik, jak z desetinné chyby e udělat celé číslo.


    
5. Zobecnění na všech 8 oktantů

    
Pseudokód z přednášky funguje jen pro x1 ≤ x2 a 0 ≤ dy ≤ dx. Pro ostatní případy (zkus je v příkladech nahoře – v pseudokódu se zvýrazní změny):

    

        
situaceúprava

        
úsečka jde doleva (x2 < x1)prohodit body A ↔ B, nebo krokovat x = x + sx, kde sx = −1

        
úsečka jde nahoru (y2 < y1)y = y + sy, kde sy = −1 (dx, dy počítat jako absolutní hodnoty)

        
strmá úsečka (|dy| > |dx|)prohodit role os: hlavní osou je y (krok v každé iteraci), x se jen občas posune; ve vzorcích se prohodí dx ↔ dy

    

    
Hlavní osa = ta, po které se posouváme v každém kroku (delší průmět úsečky). Algoritmus vykreslí vždy přesně max(|dx|, |dy|) + 1 pixelů – jeden pro každou hodnotu hlavní osy. Díky tomu nemá úsečka díry (u strmé úsečky by „krok po x“ nechal mezery – to je ten samý důvod, proč má i triviální algoritmus dvě větve).


    
6. Tipy k implementaci

    
    
        
  • Remíza p = 0 (úsečka přesně středem M): podmínka p < 0 pošle remízu do diagonály. Pozor – když úsečku kreslíš z A do B a pak z B do A s prohozením bodů, může se v remízách lišit o pixel. U polygonů a drátových modelů to obvykle nevadí, ale je dobré o tom vědět.
    • 
        
  • Degenerované případy: A = B (jeden pixel), vodorovná (dy = 0 → vždy p < 0), svislá (dx = 0 → strmá větev), úhlopříčka (dx = dy → p₀ = dy ≥ 0, d2 = 0 → vždy diagonálně). Vyzkoušej si je v příkladech.
    • 
        
  • Mimo rastr: buď ořezávat úsečku předem, nebo kontrolovat isPointInRaster(x, y) před setPixel.
    • 
        
  • Pro kontrolu můžeš výstup porovnat s LineRasterizerTrivial – mimo remízy musí dávat stejné pixely.
